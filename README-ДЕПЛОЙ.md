## ⚠️ Главное про битые картинки

Причина найдена: **картинки не битые в коде — они не догрузились на сервер.**
На `kp-sayt-6and2.surge.sh` из 16 файлов папки `assets/` реально лежат только 2
(`hero-bg.jpg` и шрифт). Остальные 14 отдают **404**:

`cab-cabinet.jpg`, `cab-copper.jpg`, `cab-luna.jpg`, `club-resident.jpg`,
`dossier-stairs.jpg`, `gal-bar.jpg`, `gal-cabinet.jpg`, `gal-entry.jpg`,
`gal-hall.jpg`, `gal-lustra.jpg`, `gal-sign.jpg`, `logo-spline-white.png`,
`menu-bar.jpg`, `strip-hall.jpg`

**Решение:** деплоить папку целиком, вместе с `assets/`. В этом архиве все файлы на месте.

```bash
# из корня распакованного архива
surge . kp-sayt-6and2.surge.sh
```

После деплоя проверить, что всё поднялось:
```bash
for f in $(ls assets/); do
  printf '%s  %s\n' "$(curl -s -o /dev/null -w '%{http_code}' https://kp-sayt-6and2.surge.sh/assets/$f)" "$f"
done
```
Все строки должны быть `200`. Если снова появятся `404` — значит клиент surge
не выгрузил вложенную папку: удалите `.surgeignore`/`CORS`-файлы, проверьте, что
`assets/` не попала в `.gitignore`, и деплойте из чистой копии.

### 8. Бронь переведена ИЗ модалки в страницу (по best practices)

Замечание справедливое. Проверил по исследованиям:
- **NN/g**, «Modal & Nonmodal Dialogs»: *«избегайте модальных диалогов, прерывающих
  высокоставочные процессы вроде checkout»* и *«если процесс изначально многошаговый —
  он, вероятно, заслуживает отдельной страницы»*;
- **NN/g**, «Overuse of Overlays»: если в оверлее появляется скролл и внутренняя
  навигация — контент должен быть полноценной страницей (пример Apple, которые
  отказались от оверлея в пользу страницы);
- **UX-фреймворк выбора modal vs page**: для многошаговых процессов индустрия
  возвращается к страницам — модалки ломают мобильный скролл (scroll-chaining),
  хуже с доступностью и «местом в иерархии»;
- **правило одной задачи**: если в модалке появляются шаги, табы и скролл — это не модалка.

**Что стало:** мастер брони живёт прямо в секции «Тапни свой стол» — аккордеон из
4 шагов (01 Стол · 02 Когда · 03 Кто · 04 Подтверждение и оплата). Активный шаг
раскрыт, пройденные свёрнуты и показывают выбранное значение справа; по клику на
заголовок пройденного шага можно вернуться и поправить. Схема зала остаётся на
экране рядом — контекст не теряется.

**Модальными остались только короткие уведомления** — ровно то, для чего модалки
и нужны по NN/g:
- результат оплаты «ПОДТВЕРЖДЕНО» / «НЕ ПРОШЛО» (одно действие, требует внимания);
- форма заявки «Обсудить вечер» / «Оставить отзыв» (одна задача, 3 поля).

### 11. Мобильное меню + докрутка адаптива

**Главная находка: на мобильном навигации не было вообще.** В медиа-запросе
стояло `.nav-links{display:none}` — ссылки просто исчезали, замены не было.

Сделано полноценное мобильное меню:
- **кнопка-бургер** в шапке (44×44, анимация в крестик при открытии);
- **полноэкранная панель-досье**: заголовок «ДЕЛО № 6/2 · РАЗДЕЛЫ», 7 разделов
  с нумерацией District (01…07) и подписями-подсказками («бар · кальяны · кухня»),
  внизу CTA «Забронировать стол», телефон и режим работы;
- закрытие: крестик, Esc, клик по разделу, авто-закрытие при растягивании до десктопа;
- блокировка скролла body, возврат фокуса на бургер, ARIA (`aria-expanded`, `aria-controls`).

**Найденные и исправленные баги адаптива:**
1. **H-скролл 1935px на десктопе** — водяной знак манифеста (`right:-30px`, шрифт 280px)
   вылезал за экран. Убран отрицательный отступ + `overflow:hidden` на секции,
   плюс глобальный предохранитель `html{overflow-x:hidden}`.
2. **Бургер не показывался** — мой CSS-блок оказался ФИЗИЧЕСКИ НИЖЕ медиа-запросов,
   поэтому базовое `.burger{display:none}` перебивало `display:block` из медиа.
   Блок перенесён выше медиа-запросов (каскад CSS зависит от порядка).
3. `.grain` с `inset:-50%` создавал ложный оверфлоу → `inset:0`.

**Докрутка мобильных стилей (≤640px, главная):**
табы меню — тап-таргет ≥40px · цена в блюде не улетает от названия (`flex-wrap`) ·
поля ввода 16px (iOS не зумит при фокусе) · чипы даты/времени крупнее ·
план зала без наклона и с меньшим padding · CTA в hero — в колонку на всю ширину ·
галерея через `aspect-ratio` вместо `min-height` · фото секций ниже (260–420px).

**Меню (menu.html), ≤760px:** карточки коктейлей в 2 колонки, ≤480px — в одну;
табы плотнее с тап-таргетом; типографика и отступы уменьшены пропорционально.

**Проверено вживую на 390×844:** без H-скролла · бургер ✓ · меню открывается
и закрывается ✓ · 7 ссылок · тап-таргет ссылки 85px · CTA 320×53 · галерея 1 колонка.

## PR4 · Бэк брони: Pages Functions + KV + Telegram (ТЗ §6, этап 4 из 4)

Фаза 0 — заявка без оплаты. Контракты §7 не менялись, middleware ↔ iikoCloud
поедет на них как есть.

- `functions/api/v1/bookings.js` — `POST /api/v1/bookings`:
  rate-limit по IP → валидация полей → проверка занятости (Фаза 0: `DEMO_BUSY`) →
  идемпотентность → запись заявки в KV → Telegram администратору → `201`.
  - **Идемпотентность (§6.2):** ключ = заголовок `Idempotency-Key`, KV `idem:*` с TTL 48 ч;
    повтор отдаёт тот же ответ (заголовок `x-idempotent-replay: true`) — без дубля
    заявки и без второго сообщения в Telegram (гейт G3).
  - **Заявки:** KV `bk:{bookingId}` без TTL (срок хранения/выгрузка — вопрос заказчику, §13).
  - **Rate-limit (§6.5):** >10 заявок/час с одного IP (`cf-connecting-ip`) → `429`
    (счётчики `rl:*` в KV, TTL 2 ч).
  - **409 `table_taken`:** конфликт слота с `DEMO_BUSY` по формуле §5; `nearestFreeAt` =
    конец занятости + буфер, вверх к сетке 30 мин; `alternatives` — до 3 свободных
    столов под число гостей.
  - **422** — ошибки по полям (телефон `+7` + 10 цифр, слот из сетки бизнес-даты,
    гости 1–12 и ≤ вместимости стола, стол из инвентаря конфига).
  - **405** на не-POST; **503 `storage_unavailable`**, если KV не привязан;
    **502 `notify_failed`**, если Telegram недоступен (заявка в KV остаётся,
    гость может повторить с тем же ключом).
- **Telegram (§6.4):** plain text без `parse_mode` — разметка из пользовательского
  ввода не интерпретируется; управляющие символы режутся на сервере.
  Env `TELEGRAM_API_BASE` — оверрайд api.telegram.org для локальных тестов (mock),
  в проде не ставится.
- **Фронт (`assets/js/booking.js`):** убрана локальная «фейк-запись» заявки при
  недоступном бэке — теперь честная ошибка `error.generic` (новая строка в
  `config.json → strings`, гейт G8). Исправлено: после success-экрана кнопка
  «Отправить заявку» и спиннер сбрасываются (`setSubmitUI(false)` — без этого
  повторная заявка была невозможна без перезагрузки).
